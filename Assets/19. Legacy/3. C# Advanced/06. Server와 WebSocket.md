# 서버와 웹소켓

> **포트 하나를 열어 두고 기다리는 프로그램.** 웹소켓은 그 위에 **끊지 않는 선**을 놓는 방식.

---

## 1. 서버는 별게 아니다

"서버" 라는 말에는 커다란 기계와 파란 불빛이 따라붙지만, 프로그램 쪽에서 보면 이게 전부.

```
켜진다  →  포트 하나를 연다  →  기다린다  →  누가 말을 걸면 답한다  →  다시 기다린다
```

**끄기 전까지 안 끝나는 반복문 하나**라고 봐도 크게 틀리지 않는다. 우리가 만들 서버는 화면도, 씬도, `MonoBehaviour` 도 없다. 검은 창 하나가 뜰 뿐이다.

이 단원에서 서버는 **내 컴퓨터에서 돈다.** 다른 기계에 올리는 것은 나중 일이고, 하는 일은 똑같다.

## 2. 주소 뜯어보기

```
ws://localhost:5000/room
└┬┘   └───┬───┘ └┬─┘└─┬─┘
 │        │      │    └── 창구 이름 (경로)
 │        │      └─────── 포트
 │        └────────────── 어느 컴퓨터인가
 └─────────────────────── 말하는 방식
```

| 조각 | 뜻 |
|---|---|
| `ws` | **웹소켓**으로 말하겠다는 뜻. 웹 페이지를 받아 올 때 쓰는 `http` 와 짝이다 |
| `localhost` | **내 컴퓨터.** 나가지 않고 자기 자신에게 건다 |
| `5000` | 포트. 한 컴퓨터에 프로그램이 여럿이라 번호로 구분한다 |
| `/room` | 창구 이름. 서버가 창구를 여럿 열어 둘 수 있다 |

**포트를 건물의 창구로 생각하면 편하다.** 컴퓨터가 건물이고, 프로그램마다 창구 번호를 하나씩 잡는다. 이미 쓰는 번호를 잡으면 `주소가 이미 사용 중` 이 뜬다.

`localhost` 는 `127.0.0.1` 과 같은 말이다. 인터넷을 끊어도 된다 — 밖으로 나가지 않기 때문이다.

## 3. 요청·응답 — 웹의 기본 방식

웹의 기본은 **묻고 답하기**다. 브라우저 주소창에 뭔가 치면 이게 일어난다.

```
클라이언트 : "체력 얼마야?"   →   서버
클라이언트   ←   "80"            서버
                              (여기서 대화가 끝난다)
```

한 번 묻고 한 번 답하면 **연결이 끊긴다.** 다음에 물으려면 처음부터 다시 붙어야 한다.

우리 서버에도 이런 창구를 하나 남겨 둔다.

```
http://localhost:5000/ping   →   pong
```

**서버가 도는지 확인하는 가장 싼 방법**이라 실제 서비스에도 대개 이런 창구가 있다. 브라우저로 열린다.

## 4. 그런데 이 방식으로는 안 되는 것이 있다

우리가 만들려는 것은 이런 것이다.

> 누가 방에 새로 들어오면, **이미 있던 사람들에게 알려 준다.**

요청·응답으로는 이게 안 된다. **서버가 먼저 말을 걸 수 없기 때문이다.**

```
[서버]  "야, 새 사람 들어왔어"   ✗  이런 건 못 한다
```

방법이 아예 없지는 않다. 받는 쪽이 **계속 물어보면** 된다.

```
0.1초마다 : "새 소식 있어?"  →  "없어"
0.1초마다 : "새 소식 있어?"  →  "없어"
0.1초마다 : "새 소식 있어?"  →  "응, 누가 들어왔어"     ← 최대 0.1초 늦게 안다
```

이걸 **폴링(polling)** 이라고 한다. 되기는 되는데 값이 비싸다.

| | 문제 |
|---|---|
| **늦는다** | 물어보는 사이의 시간만큼 늦게 안다 |
| **낭비가 크다** | 소식이 없어도 계속 묻는다. 열에 아홉은 "없어" 다 |
| **사람 수만큼 곱해진다** | 10명이 0.1초마다 물으면 초당 100번이다 |

부드럽게 하려면 자주 물어야 하고, 자주 물으면 서버가 감당해야 한다. **이 맞바꿈에서 벗어날 수가 없다.**

## 5. 웹소켓 — 끊지 않고 이어 둔다

웹소켓은 이 문제를 다르게 푼다. **한 번 붙고 나면 끊지 않는다.**

```
        ┌── 한 번 악수하고 (handshake)
        │
[클라이언트] ══════════════════ [서버]
        │
        ├─ "내 위치는 (3,1)"        →
        ←        "누가 들어왔다"    ─┤   ← 서버가 먼저 말한다
        ←        "모두의 위치야"    ─┤
        ├─ "내 위치는 (3,2)"        →
```

선이 살아 있으니 **양쪽 다 아무 때나 말할 수 있다.** 물어볼 필요가 없다.

| | 요청·응답 (HTTP) | 웹소켓 |
|---|---|---|
| 연결 | 한 번 쓰고 끊는다 | **이어 둔다** |
| 누가 먼저 말하나 | 클라이언트만 | **양쪽 다** |
| 소식을 아는 시점 | 다음에 물어볼 때 | **일어난 즉시** |
| 소식이 없을 때 | 그래도 묻는다 | 아무것도 안 오간다 |
| 적당한 일 | 게시판, 저장, 로그인 | **채팅, 위치 동기화, 실시간 알림** |

## 6. 만들 것

```
                    ┌──────────────────────────┐
                    │  서버 (Server/HelloServer)│
   [유니티 A] ══════▶│  · 들어온 사람에게 번호   │
   나 : u1           │  · 새 사람을 모두에게 알림 │
                    │  · 모두의 위치를 초당 n번  │
   [유니티 B] ══════▶│                          │
   나 : u2           └──────────────────────────┘
```

주고받는 말은 여섯 가지뿐이다.

| 방향 | 종류 | 언제 |
|---|---|---|
| 유니티 → 서버 | `hello` | 붙자마자 **한 번.** 내 이름을 알린다 |
| 서버 → 유니티 | `welcome` | 그 답. **네 번호는 이것**이고, 이미 이런 사람들이 있다 |
| 서버 → 유니티 | `join` | 누가 새로 들어왔다 |
| 서버 → 유니티 | `leave` | 누가 나갔다 |
| 유니티 → 서버 | `move` | 내 위치는 여기다 |
| 서버 → 유니티 | `state` | 지금 모두의 위치다. **초당 n번** |

오가는 것은 전부 **글자(JSON)** 다. 웹소켓이 되었다고 달라지지 않는다.

```jsonc
{ "Type": "hello", "NickName": "진" }
{ "Type": "welcome", "User": { "Id": "u1", "NickName": "진" }, "Users": [] }
```

`Type` 을 맨 앞에 두는 이유는 **무슨 말인지부터 봐야 하기 때문**이다. 종류마다 실린 것이 다르다.

## 7. 클래스가 건너가는 것이 아니다

여기가 가장 자주 오해하는 곳이다.

**클래스를 글자로 풀어서 보내고, 받은 쪽이 그 글자를 보고 자기 클래스를 새로 만든다.**

```
유니티의 HelloMessage ──ToJson──▶ {"Type":"hello",...} ──▶ 서버의 HelloMessage
     (객체)                          (그냥 글자)              (다른 객체)
```

그래서 **양쪽에 같은 모양의 클래스가 하나씩 있어야 한다.** 이 단원에서 `Contracts.cs` 라는 이름의 파일이 두 개 생기는 이유다.

```
Server/HelloServer/Contracts.cs           ← 서버 쪽
99. Local Server/Contracts.cs             ← 유니티 쪽
```

이름이 한 글자만 어긋나도 **오류 없이 빈 값**이 들어온다.

---

## 정리

- 서버는 **포트를 열고 기다리는 프로그램**이다.
- 웹의 기본은 **묻고 답하기**. 한 번 쓰고 연결을 끊는다.
- 그 방식으로는 **서버가 먼저 말을 걸 수 없다.** 알려면 계속 물어야 한다(폴링).
- 웹소켓은 **선을 이어 둔다.** 양쪽 다 아무 때나 말할 수 있다.
- 실시간에는 웹소켓, **한 번 부탁하고 끝인 일에는 요청·응답**이 낫다.
- 오가는 것은 여전히 **글자(JSON)** 다. 양쪽에 같은 클래스를 둔다.
