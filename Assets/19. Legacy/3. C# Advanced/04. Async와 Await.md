# Async와 Await
> "시간이 걸리는 일" 기다리되, 그동안
> 프로그램이 멈추지 않게 하는 문법.

`async`와 `await`는 오래 걸리는 작업
(대기, 로딩, 네트워크)을 비동기로 처리하는 
C# 문법 `await` 지점에서는 잠시 양보했다가,
작업이 끝나면 그 자리에서 이어서 실행된다.

- **동기(synchronous)**: 한 줄이 끝나야 다음 줄. 오래 걸리면 그동안 **전부 멈춘다**(게임이 얼어붙음).
- **비동기(asynchronous)**: 오래 걸리는 일은 맡겨두고 **제어를 돌려줘**, 그동안 다른 일(렌더·입력)이 돌아간다.

---

## 2. 상황

"2초 뒤에 문을 연다"를 동기로 짜면 그 2초 동안 게임 전체가 멈춘다.

```csharp
void OpenDoorAfterDelay()
{
    Thread.Sleep(2000);   // 메인 스레드를 2초간 막는다 → 화면이 얼어붙음(최악)
    door.Open();
}
```

코루틴으로 하면 멈추진 않지만, **반환값을 받기 어렵고** MonoBehaviour에 묶이며 조합이 번거롭다.

```csharp
IEnumerator OpenRoutine()
{
    yield return new WaitForSeconds(2f);   // 멈추진 않지만...
    door.Open();
    // "결과값을 돌려주는" 대기(예: 서버에서 점수 받아오기)는 코루틴으로 표현이 껄끄럽다
}
```

> **동기 대기는 게임을 얼리고, 코루틴은 값 반환·조합이 불편하다.**

---

## 3. 적용

`async` 함수 안에서 `await`로 기다리면, 게임은 안 멈추고 끝난 뒤 이어서 실행된다.

```csharp
async void Start()          // 이벤트성 진입점에서만 async void 허용 (아래 주의점)
{
    Debug.Log("문 여는 중...");
    await Task.Delay(2000); // 2초 대기 (게임은 계속 돌아감)
    door.Open();            // 대기가 끝나면 여기서 이어서
    Debug.Log("문 열림");
}
```

### 값을 돌려받는 비동기 — `async Task<T>`

```csharp
async Task<int> LoadScoreAsync()
{
    await Task.Delay(500);      // 서버 응답을 기다린다고 가정
    return 1234;                // 결과를 반환
}

async void Show()
{
    int score = await LoadScoreAsync();   // 결과를 await로 받는다
    Debug.Log($"점수: {score}");
}
```

### 핵심 규칙 몇 가지

- **`async` 함수의 반환형**: 값 없으면 `Task`, 값 있으면 `Task<T>`. (`void`는 이벤트 핸들러 전용)
- **메인 스레드 복귀**: `await` 이후 코드는 **다시 메인 스레드**에서 실행된다(Unity가 그렇게 맞춰줌).
  그래서 `await` 뒤에서 Unity API(`transform`, `GetComponent` 등)를 써도 된다.
- **예외 처리**: `try/catch`로 비동기 예외를 잡는다.
  ```csharp
  try { await LoadScoreAsync(); }
  catch (Exception e) { Debug.LogError(e); }
  ```
- **취소(맛보기)**: 오래 걸리는 작업은 `CancellationToken`으로 중간에 멈출 수 있다.
  ```csharp
  await Task.Delay(2000, cancellationToken);   // 토큰이 취소되면 대기도 취소
  ```

게임을 안 멈추면서 **값 반환·예외 처리·조합**을 자연스럽게. 코루틴보다 표현력이 높다.

## 4. Unity 가 주는 대기 — `Awaitable`

`Task` 는 C# 표준이라 **Unity 를 모른다.** 프레임도, `Time.timeScale` 도, 오브젝트 파괴도 모른다.
그래서 Unity 6 은 게임용 대기를 따로 넣어 뒀다. `UnityEngine` 안에 있어서 **설치가 필요 없다.**

```csharp
await Awaitable.NextFrameAsync();          // 다음 프레임까지
await Awaitable.WaitForSecondsAsync(2f);   // 2초 (게임 시간 기준)
await Awaitable.EndOfFrameAsync();         // 이번 프레임 렌더가 끝난 뒤
```

**시계가 다르다.** 이름이 비슷해서 놓치기 쉬운 차이다.

| | `Task.Delay(2000)` | `Awaitable.WaitForSecondsAsync(2f)` |
|---|---|---|
| 기준 | **실제 시간** — `Time.timeScale` 을 무시한다 | **게임 시간** — `timeScale` 을 따른다 |
| 일시정지(`timeScale = 0`) 하면 | 그대로 흐른다 | 같이 멈춘다 |
| 쓸 곳 | 서버 타임아웃, 재시도 간격 | 연출, 쿨다운, 대기 시간 |

### `destroyCancellationToken` — 이것 하나만 알아 가도 본전이다

`await` 뒤의 코드는 **나중에** 실행된다. 그 사이 오브젝트가 파괴되면, 이미 없는 `transform` 을 만지게 된다.
원인이 `await` 라는 걸 알아채기 어려워서 **입문자가 가장 오래 헤매는 버그**인데, 토큰 하나로 사라진다.

```csharp
private async void Start()
{
    await Awaitable.WaitForSecondsAsync(2f, destroyCancellationToken);
    transform.position = Vector3.zero;   // 파괴됐다면 여기까지 오지 않는다
}
```

`destroyCancellationToken` 은 `MonoBehaviour` 가 그냥 갖고 있다. 만들 필요도 없다.
