# **06. 미니골프 — 장애물 레벨 디자인 과제 작업지시서**

> 새 장애물을 직접 만들고, 그 장애물을 **소개 → 응용 → 심화** 세 코스에 나눠 배치해 플레이어가 배우고 익히고 시험받게 만듭니다.

---

쿠션 벽, 경사로, 아치 터널은 **모양과 물리 재질만으로**,
부스터 패드, 왕복 벽, 풍차 오브젝트는 **스크립트로** 공의 길을 바꿉니다.
이번 과제는 그 장애물을 **만드는 일**에서 한 걸음 나아가, 장애물을 **배치해서 플레이를 설계하는 일**을 연습합니다.

장애물 하나는 플레이어에게 던지는 **질문 하나**입니다.
풍차는 "날개 사이로 언제 칠래?" 라고 묻고, 난간 없는 다리는 "똑바로 칠 수 있어?" 라고 묻습니다.
코스는 그 질문을 **어떤 순서로, 어떤 조건에서** 던질지 정한 것입니다.
같은 풍차라도 넓은 평지 한가운데에 있으면 쉬운 질문이고, 낙하 구간 바로 앞에 있으면 어려운 질문이 됩니다.
**난이도는 장애물 안에 있지 않고 배치 안에 있습니다.**

### **과제 한눈에 보기**

| :-- | :--- | :--- |

## **3. 코스 세 개의 역할 — 소개 · 응용 · 심화**

세 코스는 난이도만 다른 것이 아니라 **하는 일이 다릅니다.**

```mermaid
flowchart LR
    A["소개 코스<br/>무엇인지 배운다"] --> B["응용 코스<br/>조건을 바꿔 써먹는다"]
    B --> C["심화 코스<br/>겹치고 비틀고 고른다"]
```

| | 소개 | 응용 | 심화 |
| :--- | :--- | :--- | :--- |
| 플레이어의 상태 | 이 장애물을 처음 본다 | 규칙은 안다 | 규칙을 몸으로 안다 |
| 설계자의 목표 | **안전하게 보여 준다** | **조건을 하나씩 바꾼다** | **겹치고, 비틀고, 고르게 한다** |
| 한 구간의 장애물 | 새 장애물 **하나만** | 새 장애물 + 아는 장애물 | 둘 이상이 **동시에** |
| 어렵게 만드는 손잡이(4절) | 돌리지 않는다 | 구간마다 **하나만** | 둘 이상 |
| 실패의 대가 | 작다 (튕겨 나옴) | 낙하 구간이 생긴다 | 크다 (낙하 + 먼 복귀) |
| 기준 타수(Par) 권장 | 3~4 | 4~5 | 5~6 |

**지켜야 할 규칙 하나 — 처음 보는 것을 위험한 곳에서 만나게 하지 않습니다.**
응용 코스와 심화 코스에는 소개 코스에서 보여 주지 않은 새 장애물을 **처음 등장시키지 않습니다.**
예제의 기존 장애물 여섯 종은 플레이어가 이미 안다고 봅니다.

## **난이도를 결정 짓는 요소들**

같은 장애물로 난이도를 올리고 내리는 방법은 몇 가지로 정해져 있습니다. 코스를 설계할 때는
"이 구간에서 **어떤 손잡이를 얼마나** 돌렸나" 를 말할 수 있어야 합니다.

| 손잡이 | 쉬운 쪽 | 어려운 쪽 | 참고 수치 |
| :--- | :--- | :--- | :--- |
| **통로 폭** | 레인 3 m | 다리 2 m → 외나무 0.5 m | 공 지름 0.25 m. 이보다 좁은 틈은 막힌 것과 같음 |
| **실패의 대가** | 난간이 있어 튕겨 나옴 | 난간이 없어 낙하 | 낙하하면 직전 샷 위치로 복귀 + 벌타 1 |
| **타이밍 창** | 느리게, 오래 열림 | 빠르게, 짧게 열림 | 풍차 60도/초: 1.5초마다 약 0.7초 막힘 · 왕복 벽 3초에 한 번 왕복 |
| **파워 정밀도** | 세게만 치면 됨 | 딱 알맞게 쳐야 함 | 파워 1~12 m/s, 게이지 1.5초 왕복. 평지에서 1 m/s ≈ 1 m, 6 m/s ≈ 7 m, 12 m/s ≈ 15 m |
| **조준 정밀도** | 가깝고 넓은 목표 | 멀고 좁은 목표 | 마우스 1픽셀 = 0.2도 |
| **겹침** | 장애물 사이에 쉬는 평지 | 장애물 두 개가 연달아 | 공이 멈출 자리가 있어야 "쉬는 구간" |
| **경로 선택** | 길이 하나 | 위험한 지름길 / 안전한 우회 | 우회는 1~2타 더 드는 정도가 적당 |
| **가시성** | 치기 전에 다음 장애물이 보임 | 가려져 있음 | 카메라 거리 3~10 m, 높이 15~60도 |

- **가시성은 조심해서 씁니다.** 카메라에는 충돌 처리가 없어서, 높은 벽이나 지붕이 공 가까이 있으면 카메라가 벽 너머를 비추거나 벽 속으로 들어갑니다. 벽은 난간 높이(0.3 m)를 기본으로 하고, 높은 구조물은 짧게 씁니다.
- **공정함을 잃지 않습니다.** 어렵더라도 "보고 나면 풀 수 있어야" 합니다. 운만으로 결정되는 구간은 난이도가 아니라 벌입니다.

### **아이디어 예시**

아래에서 골라도 되고, 직접 생각한 것이어도 됩니다. ★ 가 많을수록 구현이 어렵습니다.

| 아이디어 | 종류 | 난이도 | 출발점 · 힌트 |
| :--- | :--- | :-- | :--- |
| 외나무다리 | 모양 | ★ | 폭 0.5 m 바닥, 난간 없음 — 조준 정밀도를 묻는다 |
| 얼음 바닥 | 재질 | ★ | Physics Material 마찰 0, Friction Combine **Minimum** — 공이 덜 느려져 멀리 간다 |
| 범퍼 기둥 | 재질 | ★ | 쿠션 벽의 `PM_Bouncy` 를 기둥에. 핀볼처럼 여러 개 |
| 깔때기 · 반파이프 | 모양 | ★★ | ProBuilder 로 만들고 **Mesh Collider** (아치 터널 참고) |
| 모래 벙커 (감속 구역) | 트리거 + 힘 | ★★ | `BoostPad` 를 읽고 시작. 속도 반대 방향으로 가속하면 감속이 된다 |
| 컨베이어 · 옆바람 | 트리거 + 힘 | ★★ | 방향을 레인과 다르게. **6.4 멈추지 못하는 공** 주의 |
| 점프 패드 | 트리거 + 힘 | ★★ | 들어오는 순간 한 번만 위로 속도를 더한다(`OnTriggerEnter`, `ForceMode.VelocityChange`) |
| 오르내리는 문 | Kinematic | ★★ | `KinematicShuttle` 의 `offset` 을 위쪽으로 |
| 회전 원판 | Kinematic | ★★ | `KinematicSpinner` + 납작한 원판. **Cylinder 기본 콜라이더는 캡슐**이라 납작하게 줄여도 둥글게 부푼 모양으로 닿는다 — Mesh Collider 로 바꾼다 |
| 스위치 문 | 참조 연결 | ★★★ | 스위치(트리거)가 `[SerializeField]` 로 받은 문을 연다. 문은 Kinematic + `MovePosition` |
| 워프 홀 | 순간이동 | ★★★ | Rigidbody `position` 과 `transform.position` 을 **둘 다** 옮기고 `CinemachineCore.OnTargetObjectWarped` 로 카메라에 알린다(`GolfGameManager` 의 `ReturnBall` 참고) |
| 시소 · 흔들다리 | Dynamic + Joint | ★★★ | `HingeJoint` — 수업 범위 밖의 도전 과제 |
